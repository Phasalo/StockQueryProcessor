# Интерфейс склада

Запуск из корня проекта:

```powershell
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe main.py
```

Открыть `http://localhost:5000/`. Настройки PostgreSQL находятся в `config.py`, пароль — в `.env` (`POSTGRESQL_PASSWORD`). Flask напрямую вызывает `WarehouseReports` и передаёт данные в Jinja. Отдельного JSON API нет. Приложение только читает данные.

- `/film-type/BOPP` — сводка по типу плёнки.
- `/film` — переход к первой существующей комбинации BOPP.
- `/film-type/BOPP/1200/25` — детализация комбинации.
- `/transactions` — журнал, доступный только по прямому адресу.

Фильтры сохраняются в пути URL. После изменения браузер через fetch получает HTML того же маршрута и заменяет содержимое страницы; назад/вперёд работают через popstate. Первая загрузка сразу содержит данные, без дополнительных запросов. После смены типа выбранные формат и толщина сохраняются, даже если их нет в справочниках нового типа. Отсутствующая комбинация показывает пустые таблицы и нулевые итоги, включая прямой заход и F5. Неизвестный тип возвращает 404.

Выгрузки `/exports/film-type/...` и `/exports/transactions` содержат все строки выбранного отчёта, независимо от поиска и сортировки DataTables. На главной странице доступны только два перехода, без выгрузки.

Дата и время входят в имя Excel-файла. В журнале время формирования находится в A1, заголовки — в строке 2. В сводке A1 содержит тип плёнки, A2 — время формирования, строка 3 — заголовки. На каждом листе детализации A1–C1 содержат тип плёнки, формат и толщину, A2 — время формирования, строка 3 — заголовки.

Количество планируемого расхода приходит из БД отрицательным и сохраняет этот знак в веб-таблицах и Excel. Вес в Excel остаётся числом с двумя знаками после запятой, без «кг» в ячейках.

Четыре компонента Jinja: `base.html`, `_data_block.html`, `_header_fields.html`, `_datatable.html`. Приложение создаётся в `app/__init__.py`, маршруты находятся в `app/views.py`. Форматирование чисел и дат — в `app/formatting.py`, колонки — в `app/ui_schema.py`. JavaScript в `app/static/reports.js` подключает DataTables и заменяет HTML при смене фильтров. Скачивание Excel работает обычной ссылкой. Bootstrap, jQuery и DataTables загружаются с CDN, для них нужен доступ к интернету.

Отчётные страницы используют общий порядок: навигация → заголовок → поиск и Excel → фильтры, если есть → данные. Поиск детализации одновременно фильтрует расход и приход; итоги и выгрузка относятся ко всей выбранной комбинации. Поиск и сортировка не меняют состав Excel; выгружается полный отчёт по фильтрам из URL. Журнал доступен только по прямому адресу. Главная и страницы ошибок используют общие навигацию и заголовок без панели отчёта.

Отступы заданы в `app/static/reports.css` шкалой 4, 8, 16, 32, 64 px. Предыдущие Bootstrap-классы отступов удалены, стандартные отступы компонентов сброшены. 4 px связывают подпись и поле, 8 px отделяют заголовок блока от таблицы, 16 px — элементы одной группы управления, 32 px — разделы и блоки данных. На узком экране внешние поля уменьшаются с 32 до 16 px. 64 px оставлены в шкале для будущих крупных разделов.

Проверки без подключения к PostgreSQL:

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
```
