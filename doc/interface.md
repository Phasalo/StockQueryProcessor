# Интерфейс склада

Запуск из корня проекта с установленным uv. Версия Python указана в `.python-version`, зависимости — в `pyproject.toml` и `uv.lock`:

При сборке `psycopg2` из исходников нужен `pg_config` из PostgreSQL в `PATH`. Для PostgreSQL 16 из Homebrew: `export PATH="$(brew --prefix postgresql@16)/bin:$PATH"`.

```sh
uv sync --locked
uv run --locked python main.py
```

Открыть `http://localhost:5000/`. Настройки PostgreSQL находятся в `config.py`, пароль — в `.env` (`POSTGRESQL_PASSWORD`). Flask напрямую вызывает `WarehouseReports` и передаёт данные в Jinja. Отдельного JSON API нет. Приложение только читает данные.

- `/film-type/BOPP` — сводка по типу плёнки.
- `/film` — переход к первой существующей комбинации BOPP.
- `/film-type/BOPP/1200/25` — детализация комбинации.
- `/transactions` — журнал, доступный только по прямому адресу.

Тип и размеры сохраняются в пути URL, марка — в параметре `brand`. После изменения браузер через fetch получает HTML того же маршрута и заменяет содержимое страницы; назад/вперёд работают через popstate. Первая загрузка сразу содержит данные, без дополнительных запросов. После смены типа выбранные формат и толщина сохраняются, даже если их нет в справочниках нового типа. Отсутствующая комбинация показывает пустые таблицы и нулевые итоги, включая прямой заход и F5. Для нескольких марок с одинаковыми размерами требуется выбрать марку; до выбора расчёт не показывается и выгрузка отключена. При единственной марке она выбирается автоматически. Изменение типа или размеров сбрасывает марку, ссылка из сводки выбирает её явно. Неизвестный тип возвращает 404.

Выгрузки `/exports/film-type/...` и `/exports/transactions` содержат все строки выбранного отчёта, независимо от поиска и сортировки DataTables. На главной странице доступны только два перехода, без выгрузки.

Дата и время входят в имя Excel-файла. В журнале время формирования находится в A1, заголовки — в строке 2. В сводке A1 содержит тип плёнки, A2 — время формирования, строка 3 — заголовки. На каждом листе детализации A1–C1 содержат тип плёнки, формат и толщину, D1 — выбранную марку, если она есть, A2 — время формирования, строка 3 — заголовки.

Количество планируемого расхода приходит из БД отрицательным и сохраняет этот знак в веб-таблицах и Excel. Вес в Excel остаётся числом с двумя знаками после запятой, без «кг» в ячейках.

Журнал читает новую схему через `ReportRepository`: исходные количества планов сохраняются после отмен и исполнения. Для фактического расхода показываются заказчик, производственная карта и фактическая дата, если она указана; для прихода без плана — поставщик факта. Название типа плёнки берётся из БД, включая типы за пределами Python `FilmType`.

Сводки показывают отдельные марки, физический, доступный («Свободный») и прогнозный остатки. Физический остаток равен сумме RECEIPT, ISSUE и ADJUSTMENT; доступный — физическому минус открытый резерв; прогнозный — доступному плюс открытые планы прихода. В детализации планов показано количество за вычетом отмен; исполненные и полностью отменённые планы исключены. Все отчётные методы используют новую схему через ReportRepository и UnitOfWork.

Четыре компонента Jinja: `base.html`, `_data_block.html`, `_header_fields.html`, `_datatable.html`. Приложение создаётся в `app/__init__.py`, маршруты находятся в `app/views.py`. Форматирование чисел и дат — в `app/formatting.py`, колонки — в `app/ui_schema.py`. JavaScript в `app/static/reports.js` подключает DataTables и заменяет HTML при смене фильтров. Скачивание Excel работает обычной ссылкой. Bootstrap, jQuery и DataTables загружаются с CDN, для них нужен доступ к интернету.

Отчётные страницы используют общий порядок: навигация → заголовок → поиск и Excel → фильтры, если есть → данные. Поиск детализации одновременно фильтрует расход и приход; итоги и выгрузка относятся ко всей выбранной комбинации. Поиск и сортировка не меняют состав Excel; выгружается полный отчёт по фильтрам из URL. Журнал доступен только по прямому адресу. Главная и страницы ошибок используют общие навигацию и заголовок без панели отчёта.

Отступы заданы в `app/static/reports.css` шкалой 4, 8, 16, 32, 64 px. Предыдущие Bootstrap-классы отступов удалены, стандартные отступы компонентов сброшены. 4 px связывают подпись и поле, 8 px отделяют заголовок блока от таблицы, 16 px — элементы одной группы управления, 32 px — разделы и блоки данных. На узком экране внешние поля уменьшаются с 32 до 16 px. 64 px оставлены в шкале для будущих крупных разделов.

Проверки без подключения к PostgreSQL:

```sh
uv run --locked python -m unittest discover -s tests -v
uv run --locked ruff check .
```
